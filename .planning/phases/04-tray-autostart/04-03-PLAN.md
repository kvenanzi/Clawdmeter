<objective>
Vertical slice — connection-status surfacing (SC#2, SC#3). Bring up the pystray
tray app that is the user-visible face of the daemon: one constant brand mark
(from 04-01 icon_assets) with a colored corner bubble + tooltip showing
connected / scanning / error, a menu with a non-clickable status header, a
checkable "Start at login" toggle (driving 04-02 autostart), and Quit. The
unchanged Phase 2/3 daemon loop runs in a background thread (RESEARCH Pattern 1:
asyncio in bg-thread, pystray on main thread); a thread-safe `TrayState` bridges
loop->tray, and Quit routes tray->loop through the existing `stop_event` via
`loop.call_soon_threadsafe` for a clean disconnect (SC#3). The only daemon edit
is additive: inject `set_connected/set_scanning/set_error` calls at the existing
decision points — loop logic stays untouched (D locked).

Purpose: Deliver the user-observable capability that defines this phase — a tray
icon you can glance at to know the Clawdmeter is connected, plus a clean Quit —
on top of the already-shipped loop, without restructuring it.
Output: `daemon/tray_windows.py`, additive TrayState wiring in the daemon,
`pystray`+`Pillow` in requirements, and unit tests for the pure glue.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| daemon loop (bg thread) -> tray (main thread) | Cross-thread state hand-off; asyncio.Event is not thread-safe |
| tray menu -> autostart registry | Start-at-login toggle writes the HKCU Run persistence hook |
| daemon -> tray tooltip/toast | The OAuth token flows through the wrapped loop; new tray surfaces must not leak it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06 | Tampering | Quit / stop_event cross-thread set | mitigate | Route Quit through `loop.call_soon_threadsafe(stop_event.set)` only — never set the asyncio.Event from the tray thread (RESEARCH Pitfall 2); prevents a corrupted/lost shutdown signal |
| T-04-07 | Information Disclosure | tray tooltip / status header / Error toast | mitigate | Surface only state + last-sync time + the fixed "token expired — run claude login" string (D-04) — NEVER the token value; no new token logging added (ASVS V7); the D-10 "log resolved token path" idea was explicitly not adopted |
| T-04-08 | Denial of Service | tray refresh loop | accept | A ~1s passive poll for state change is cheap and bounded; icons are built once at startup (not per tick) so there is no runaway compositing cost |
| T-04-SC | Tampering | pip installs (pystray, Pillow) | mitigate | RESEARCH "Package Legitimacy Audit": slopcheck 0.6.1 ran clean 3/3 [OK], both [VERIFIED: PyPI] — no [ASSUMED]/[SUS]/[SLOP], so no blocking-human checkpoint required; installs happen via install-windows.ps1 (04-04) against the pinned requirements file |
