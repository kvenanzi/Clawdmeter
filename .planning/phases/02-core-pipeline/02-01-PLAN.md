<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| daemon → api.anthropic.com | OAuth bearer token leaves the host over HTTPS; untrusted response headers cross back in |
| credentials file → daemon | OAuth token read from local disk (Phase 1 `read_token`) flows into `poll_api` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | OAuth token in poll_api / logs | mitigate | Token passed only as `Authorization: Bearer` header; never logged. `log()` calls must not include the token string. Tests assert no token value appears in stdout patterns. |
| T-02-02 | Tampering / MITM | HTTPS to api.anthropic.com | mitigate | Use `httpx.AsyncClient` with default TLS verification ON; do NOT pass `verify=False`. ASVS L1 satisfied by default cert validation. |
| T-02-03 | Tampering | response header parsing | accept | Malformed/absent ratelimit headers fall back to 0 / "unknown" via pct/reset_minutes ValueError handling — no crash, no injection vector (values become ints/strings only). |
| T-02-SC | Tampering | pip installs (bleak, httpx) from requirements-windows.txt | mitigate | Both are well-known PyPI packages (bleak: hbldh; httpx: encode). See Plan 02 legitimacy checkpoint before any install on hardware; no install runs in this plan's automated verify (logic tests don't need bleak imported at runtime path — but the module imports bleak at top, so the test env must have bleak+httpx; both are already present in this repo's dev env per pre-check). |
</threat_model>
