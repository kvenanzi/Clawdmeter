<objective>
Build the BLE end-to-end glue on top of Plan 01's polling logic so the Windows
daemon becomes a working pipeline: scan for "Claude Controller", connect over WinRT
with the locked kwargs, subscribe to the device's refresh request, poll the API, and
write the usage JSON to the GATT RX characteristic — wrapped in a scan/connect/backoff
run loop driven by `asyncio.run(main())`.

Purpose: BLE-01 (discover + connect via WinRT, scan-first, `address_type="random"`,
`use_cached_services=False`) and BLE-02 (write usage JSON to the unchanged GATT data
service). Per D-10 this is hardware-bound glue verified manually on Windows (Plan 03),
not mocked-bleak integration-tested. This plan completes the vertical slice: after it,
a Windows operator can run the daemon and the device should leave its waiting screen.

Output: `scan_for_device`, `Session`, `connect_and_run`, `main`, and the `__main__`
async runner added to `claude_usage_daemon_windows.py` (Phase 1 + Plan 01 code intact).

This plan is `autonomous: false` because it opens with a blocking package-legitimacy
checkpoint before the bleak-importing code is run on hardware.
