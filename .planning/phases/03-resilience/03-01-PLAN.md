<objective>
Harden `connect_and_run()` in the Windows daemon with two reconnect defenses, each
landing with its guarding unit test (TDD):

- **D-01 — connect-retry wrapper:** wrap the `BleakClient` construction + `connect()` +
  `is_connected` check in a short N-attempt retry (≈3 tries, ~2s apart, with a guarded
  `disconnect()`-and-rebuild between attempts) to defeat the post-wake WinRT failure modes
  (`Could not get GATT services: Unreachable`, stale `is_connected`). Only after the
  retries exhaust does `connect_and_run` return its failure value and let the outer loop
  re-scan.
- **D-03 — zombie-link break:** track consecutive failed poll/write cycles inside the
  `while client.is_connected` loop and `break` after N failures (default 1), so a half-open
  link (WinRT reports `is_connected=True` but writes silently fail) is abandoned instead
  of trapping the loop forever.

Both changes live inside the single function `connect_and_run` (one analog: itself),
reuse patterns already in the file, and add NO new GATT traffic (honors Phase 2 D-08
"no TX read"). Polling/payload logic is untouched (Phase 2 D-02: "wrap connect(), don't
rewrite the loop").

Purpose: Satisfies the connect-path half of BLE-03 — the daemon recovers from sleep/wake
and out-of-range half-open links without a restart, well inside the 120s SLA.
Output: hardened `connect_and_run`, new `daemon/tests/test_windows_reconnect.py`.
</objective>
