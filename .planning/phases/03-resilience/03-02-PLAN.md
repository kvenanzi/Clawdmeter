<objective>
Split the single shared `backoff` counter in `main()` into two regimes (D-05), so a lost
known-good link recovers fast (low cap, protecting the 120s SC#1–3 SLA) while a genuinely
absent device backs off gently (existing 60s cap, no scan hammering):

- **`if not device:` (scan returned None) → slow-search regime** — `search_backoff`,
  doubling toward a 60s cap (current behavior, renamed/preserved).
- **`if not ok:` after `connect_and_run` (had/attempted a link that dropped) →
  fast-reconnect regime** — `reconnect_backoff`, doubling toward a ~5–10s cap.

The interruptible-wait idiom (`asyncio.wait_for(stop_event.wait(), timeout=...)` +
`except asyncio.TimeoutError`) is reused VERBATIM for both regimes so SIGINT/SIGTERM stay
responsive during backoff sleeps. `scan_for_device()`, `poll_api`, `Session`, `read_token`
are untouched; D-04 keeps scan-every-cycle (no MAC cache). Copy the macOS `main()` outer-loop
*shape*, NOT its platform branches (drop `skip_addr`/`retrieve_connected_macos` and the
Linux `SAVED_ADDR_FILE` invalidation — Windows is stateless).

Purpose: Satisfies the backoff half of BLE-03 — stacked transient failures cannot push
reconnect latency past the 120s budget, while an absent device is not hammered. Depends on
03-01 because it modifies the same file (sequential, no merge conflict).
Output: hardened `main()`, D-05 tests appended to `daemon/tests/test_windows_reconnect.py`.
</objective>
